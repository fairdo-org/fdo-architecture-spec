FDO Records

This section is normative.

[R-REC-1] FDO record

A PID identifying an FDO MUST resolve into a structured information record, called the FDO Record.

[R-REC-2] FDO attribute tuples

A FDO Record consists of a finite number of FDO attributes (short: attributes). Each attribute instantiates properties of the identified resource. As such, an attribute consists of at least a label for the property and a value. The property MAY be further enriched with additional semantics and validation rules (see attribute definitions). Properties do NOT need to be unique in an FDO record.

Attributes MUST be implemented as n-tuples, with n≥2. With n=2 as the smallest permitted order of tuples, this document uses 2-tuples for the definitions and requirements. Any FDO implementation MAY use higher-order tuples to implement attributes, provided that the requirements described in this document are met. The upper limit on the number of tuples per record> depends on the specific implementation.

[R-REC-3] Minimum requirements for FDO records

All FDO records MUST contain the attributes from the 0.FDO/Root profile:
  • 0.FDO/Profile or FDO_Profile
  • 0.FDO/Typeor FDO_Type
  • 0.FDO/Dataor FDO_Data

[R-REC-4] 0.FDO/Profile attribute

Every FDO record MUST be linked via a PID to at least one FDO profile, which it complies to. This is done using the designated 0.FDO/Profile attribute in its FDO Record. To link multiple FDO Profiles, the attribute 0.FDO/Profile MAY be repeated multiple times in the FDO Record.

[R-REC-5] 0.FDO/Type attribute

Each FDO MUST specify its FDO type using the designated 0.FDO/Type attribute. To link multiple FDO types, the attribute 0.FDO/Type MAY be repeated multiple times in the FDO Record. 0.FDO/Type follows the attribute referencing mechanism.

[R-REC-6] 0.FDO/Data attribute

Each FDO MUST contain the designated 0.FDO/Data attribute at least once. The attribute 0.FDO/Data is used to reference the FDO's data. It uses the attribute referencing mechanism.
