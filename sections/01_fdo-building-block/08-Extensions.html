Extensions

Concepts and mechanisms that are part of this section are not essential for the basic functionality of FDOs but provide additional features that can be used to extend the capabilities of FDOs. Thus, clients and implementations of FDOs (that follow section ) MAY choose to support these features, but they are not required to do so.

Inline FDOs

When using profile referencing, an attribute references another FDO, for example, a=(<attr_def>,<PID resolving to other FDO>). However, rather than referencing the other FDO, it may be serialized directly as the in-line value of a. In this case, the serialization depends on the implementation, and the implementation MUST specify the serialization format, if it decides to support this feature. Furthermore, inline FDOs typically do NOT have their own PIDs and are hence NOT suited for attribute definitions, syntax definitions or profile definitions.

External Vocabulary Referencing

In some cases, it will be useful to reuse existing vocabularies, ontologies, and terminologies in FDO records. For example, existing, specific metadata could be added this way (even if vocabulary terms do not fulfill the same guarantees as attribute definitions). Using a vocabulary term as an attribute in an FDO record similar to an attribute definition is explicitly supported as a community attribute. Vocabulary terms can also be used as the value of an attribute in an FDO record. Both variants can be realized by applying the external vocabulary referencing mechanism, which is specified in the following.

[R8-1] Declaration of External Vocabulary Usage in an Attribute Definition

If an attribute definition A is supposed to use external vocabulary referencing it MUST explicitly state so by instantiating the 0.FDO/AttributeDefVocabularyRef profile. 0.FDO/AttributeDefVocabularyRef is an attribute validation mechanism and as such MUST extend 0.FDO/AttributeDef. It additionally requires that the 0.FDO/ImportVocabulary attribute of A MUST refer to an FDO that follows the profile definition 0.FDO/VocabularyDef.

[R8-2] Declaration of External Vocabulary Usage in an FDO record

To use external vocabulary terms as attribute definitions in an FDO record, the record MUST contain the 0.FDO/ImportVocabulary attribute. Values of the 0.FDO/ImportVocabulary attribute MUST refer to an FDO that follows the profile definition 0.FDO/VocabularyDef. This attribute indicates to a client which vocabularies are used in an FDO, allowing a client to automatically detect and resolve vocabulary terms in an FDO using the prefixes specified by the vocabulary definition. The 0.FDO/ImportVocabulary attribute MAY be used multiple times in an FDO record to import multiple vocabularies. The creator of an FDO record MUST ensure that the prefixes of the imported vocabularies are unique.

The vocabulary definition profile (0.FDO/VocabularyDef) specifies which information is needed to describe a vocabulary. FDOs instantiating this profile MUST define values for the 0.FDO/Name, and 0.FDO/VocabularyPrefix attributes.

To enable automatic validation of vocabulary terms, the FDO SHOULD also specify how the vocabulary can be retrieved (using 0.FDO/Data), the format in which the vocabulary is provided (0.FDO/VocabularyFormat), and a SPARQL query that checks the validity of the vocabulary term (0.FDO/SPARQL_Check).

Optionally, 0.FDO/Description, 0.FDO/Contact, 0.FDO/LandingPage, and other attributes MAY be used to provide additional information about the vocabulary.

  • The attribute definition 0.FDO/ImportVocabulary accepts profile references to FDOs that follow the profile definition 0.FDO/VocabularyDef. This means that 0.FDO/ImportVocabulary indicates to a client which vocabularies are used in an FDO.
  • The profile definition 0.FDO/VocabularyDef specifies which information is needed to describe a vocabulary. This information MUST provide meaningful information of the vocabulary and SHOULD allow a client to automatically validate the usage of terms from this vocabulary. It MUST also enable a client to automatically detect the use of vocabulary terms in an FDO using a prefix. The reason why validation is not mandatory is that some vocabularies MAY NOT provide a machine-readable version of the vocabulary in one of the pre-defined file formats (e.g., RDF/XML, TTL, N-Quads, or JSON-LD). A fixed list of such file formats is needed for implementation.
  • 21.example/SchemaOrg uses the 0.FDO/VocabularyDef profile to describe the schema.org vocabulary. This FDO contains some metadata about the schema.org vocabulary, such as its name, description, and a URL to a landing page. It also specifies the prefixes that can be used to reference schema.org terms in an FDO, enabling clients to determine to which (if any) vocabulary a term belongs (in this case schema: and https://schema.org/). To enable automatic validation of schema.org terms, the FDO 21.example/SchemaOrg also specifies how the schema.org vocabulary can be retrieved (using 0.FDO/Data) the format in which the vocabulary is provided (0.FDO/VocabularyFormat), and a SPARQL query that is executed on the downloaded vocabulary with the $TERM$ argument to determine if the term is included in the vocabulary.
  • The FDO 21.123/example4 contains the attribute (0.FDO/ImportVocabulary, 21.example/SchemaOrg) to indicate that it uses the schema.org vocabulary described in 21.example/SchemaOrg. Afterward, any schema.org term can be used as an attribute in the form (<prefix + term>, <value>), such as (https://schema.org/priceCurrency, USD). A client automatically detects that e.g., https://schema.org/priceCurrency is a schema.org term because it starts with the prefix https://schema.org/, which is specified in the FDO 21.example/SchemaOrg.

External vocabulary referencing can also be used to reference a term from an external vocabulary as the value of an attribute (see ). In this case, the attribute definition that applies external vocabulary referencing refers to an FDO that instantiates the 0.FDO/VocabularyDef profile. The value of the attribute is then a reference to a term in this vocabulary.

This example shows how the attribute definition 21.example/TypeOfWork uses external vocabulary referencing. It refers to the FDO 21.example/SchemaOrgCreativeWork, which instantiates the profile definition 0.FDO/VocabularyDef and validates that the term is a subclass of CreativeWork. Creating 21.example/SchemaOrgCreativeWork is necessary to express and validate the constraint to only subclasses of CreativeWork. The attribute (21.example/TypeOfWork, schema:Photograph) in the FDO record 21.123/example5 is valid because the term https://schema.org/Photograph is a subclass of CreativeWork.
