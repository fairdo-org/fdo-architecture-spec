[S-10]: FDO Data Access

This step attempts to return the FDO’s data bit-sequence or a reference to it. It assumes that was completed and that its status indicates that a 0.FDO/Data field is present (a Mandatory_Attributes_Status of COMPLETE, DATA_ONLY, TYPE_MISSING, or PROFILE_MISSING).
Inputs
This step expects that had a Mandatory_Attributes_Status of COMPLETE, DATA_ONLY, TYPE_MISSING, or PROFILE_MISSING. The Validated_Profiles with their respective attributes from .
Outputs
An object is returned which consists of the following elements:
  • Data_Extraction_Status:
    • SUCCESS: All 0.FDO/Data attributes are valid, i.e., they all either contain the element self or they point to another attribute in the record.
    • PARTIAL_SUCCESS: Some 0.FDO/Data attributes are valid.
    • FAILURE: No 0.FDO/Data attributes is valid.
  • Data_Attributes: a list of attributes, each of which contains data either inline, by reference, or its value is self. In the latter case, the record is itself the data of the FDO.
Expected behavior
The 0.FDO/Data attribute by definition either has as its value the string self, or it uses the attribute referencing mechanism to point to other attributes in the record that contains data either by reference or inline. The client locates all 0.FDO/Data attributes in the FDO record. For each of them it performs the following steps:
  • If the 0.FDO/Data attribute has the value self, then (0.FDO/DataAsSelf, self) is added to Data_Attributes. Proceed to the next 0.FDO/Data.
  • If the 0.FDO/Data attribute has a different value, it is assumed that the attribute referencing mechanism is applied. It is checked whether this value appears in any other attribute as first element. All such other attributes which are found in the record (0.FDO/Data is said to be pointing to those via attribute referencing) are added to Data_Attributes. Proceed to the next 0.FDO/Data.
The Data_Extraction_Status is determined as follows:
  • If the Data_Attributes list is empty, then the Data_Extraction_Status is FAILURE.
  • Else if there are 0.FDO/Data attributes in the record whose value is not self and which do not point anywhere, the Data_Extraction_Status is set to PARTIAL_SUCCESS.
  • Else, all data elements were found and the Data_Extraction_Status is set to SUCCESS.
The client should make the best effort to provide the means to access the data collected in the Data_Attributes list depending on the manner in which the FDO includes its data. To do so, he may first inspect the attribute definitions of the attributes in the Data_Attributes list to find further information or instructions.
This example shows an FDO record 10.1234/000 with three 0.FDO/Data attributes.

10.1234/000
0.FDO/Type 0.example/ResourceTypeGeneral
0.example/ResourceTypeGeneral 0.example/Collection
0.FDO/Profile 10.123/Profile100
0.FDO/Data 0.example/HttpUrl
0.example/HttpUrl www.my-file.com
0.example/HttpUrl www.my-file-2.com
0.example/Description This FDO consists of several data bit-sequences.
0.FDO/Data 0.example/FdoRef
0.example/FdoRef 21.abc/def
0.FDO/Data 0.example/InlineData

Applying the processing step returns
  • Data_Extraction_Status: PARTIAL_SUCCESS, because 0.example/InlineData does not point anywhere in the record
  • Data_Attributes: [(0.example/HttpUrl, www.my-file.com), (0.example/HttpUrl, www.my-file-2.com), (0.example/FdoRef, 21.abc/def)]. The client may continue by attempting to follow those references.
