[S-1]: Detection of PIDs

This step MUST determine if the provided string is an identifier, whether it is potentially resolvable and how. This MAY be achieved using any technical solution such as a regular expression based analysis aware of the well known resolvable ID systems. This process MAY result in false positives, but MUST avoid false negatives.

Inputs
The input is an arbitrary string.
Outputs
  • If the analysis is successful it returns one or more of the following IdentifierResolvers structures consisting of:
    • A syntactically valid identifier (there MAY be multiple outcomes).
    • A ResolverList with 0 or more resolvers by name in order of probability that MAY resolve the identifier. The resolver SHOULD be identified as an FDO.
  • If the analysis fails, it throws an exception UNRECOGNIZED_IDENTIFIER.
Expected behavior

This step will iterate through a set of well-known identifier technologies. Each client MAY have its own list that it will use when performing this step. A list of identifier technologies SHALL be maintained by the FDO Forum and be updated by the various FDO implementations and by the community at large. These FDOs will include information about the identifier syntax and resolvers.

The input string is https://dx.doi.org/10.500/123. [S-1] Detection of PIDs would process this as known DOI. There would be two instances of the IdentifierResolvers structure:

    • Identifier: https://dx.doi.org/10.500/123
    • ResolverList: 0.example/DNS_RESOLVER
    • Identifier: 10.500/123
    • ResolversList: 0.example/DOI_RESOLVER, 0.example/HDL_RESOLVER

The input string is https://www.ACME.org/fdo/123-245-232. [S-1] Detection of PIDs would determine that this is a valid URI and that it could be an FDO because of the “fdo” in path name. But while 123-245-232 looks like an identifier, no known resolver can be found. [S-1] would generate an IdentifierResolvers with the following values:

  • Identifier: https://www.ACME.org/fdo/123-245-232
  • ResolverList: 0.example/DNS_RESOLVER
