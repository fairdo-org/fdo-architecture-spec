Granularity of FDOs

The granularity of FDOs depends on the pragmatic utility decisions made within communities of practice. When representing a resource as an FDO, it is necessary to consider its various parts and their respective relationships to encapsulate then in a manner that best represents the resource and its use. The granularity of an FDO depends on the need to balance flexibility, simplicity and manageability in creating, updating, and accessing the resources. There are a few general considerations and options in determining the granularity of an FDOsuch as:

  • Deciding if a resource is to be represented in-line within the or by reference as separate FDOs.
  • Deciding if a resource bit sequences should be split into multiple parts in-line within an FDO or in new FDOS.
  • Using collections mechanisms to aggregate multiple in-line or by reference parts.
Whatever granularity is chosen at the time of the creation of an FDO it is not final and can be changed as needed.

An example is MRI scans of the brain. One option is to create one FDO for the entire set of slices. Another option is to create one FDO for each slice, with attributes indicating which slice it is.

The individul granularity requirements are described in the following sections.

[R2-1] Single resource Representation

Each FDO represents exactly one resource. The resource MAY be simple or complex consisting of multiple resources.

[R2-2] Collection Definition

An FDO is called a collection FDO if it represents a resource that consists of multiple resources that can be specified in the FDO Record as in-line bit-sequences or by reference as an FDO. This ultimate granularity of and FDO dependends on pragmatic utility decisions originating within communities of practices. A collection FDO, is identified by a PID, described by the metadata in its FDO record, and able to describe the structure of its resource collection within its FDO record. Collections can include other collections.

[R2-3] Resource Description

A resource MUST be locatable within and FDO using FDO attributes. If present, it MAY have associated data bit-sequence(s), or a reference.

[R2-4] Attribute Scope

Every FDO attribute in an FDO record MUST only describe the FDO's identified resource. Even if the FDO is a collection, all attributes within the FDO record MUST describe theresource as a whole or each of it individual parts. To describe one of the parts of the resource with FDO attributes, extract this part into its own FDO record, define an Inline FDO, or use a Composite Attribute .
