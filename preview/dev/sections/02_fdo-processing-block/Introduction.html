Introduction

The generic FDO processing consists of a set of 11 steps that a FDO client may execute in order to access an FDO and all its components, given its PID. This specification uses these steps to describe the function and characteristic of the various components of the FDO.

All FDO implementations should describe how their approach satisfies the following set of steps in an implementation profile (see ). FDO implementations are not required to implement each of these steps as long as they can account for how their implicit assumptions and different components achieve the same results.

Given a string, determine if it is a PID that can be resolved.
Resolve the PID into a PID record.
Parse the PID record into a set of FDO attributes.
Locate all mandatory FDO attributes.
Determine if the FDO has one or more type(s) and whether they are appropriate given the requirements of the client.
Determine if the FDO has one or more profile(s) and whether they are appropriate given the requirements of the client.
Validate the FDO record against the profile(s) that are of interest to the client.
Validate the FDO attributes against their attribute definition(s) that are of interest to the client..
Determine if the FDO's data is of interest to the client, given the FDO attributes in the FDO record.
The client accesses the FDO’s data subject to access control.
Validate if the FDO’s data matches the type(s) of the FDO.
