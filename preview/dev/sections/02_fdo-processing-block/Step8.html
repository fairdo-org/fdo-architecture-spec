[S-8]: FDO Attributes Validation

The step assumes that successfully validated one or more profiles resulting in one or more sets of attributes. For each attribute, this step determines if the attribute's value is appropriate given its validation rules. The validation itself will greatly vary in complexity depending on the rules of the specific attribute.
Inputs
The inputs consist of the list of Validated_Profile (especially Valid_Attributes and Invalid_Attributes) from . Even if the cardinality of some attributes was not valid (Invalid_Attributes), a validation of the attribute's value against its attribute definition may still be performed. Note that this step could be used with any attribute list that would need validation.
Outputs
The output will be a list of Validated_Attribute where each attribute will have an Attribute_Validation_Status and an Error_Description. The Attribute_Validation_Status will include, but is not limited to, the following list:
  • VALID: Indicates that the value is appropriate according to the validation rules.
  • PARTIALLY_VALID: Indicates that the value is partially valid. An example is the case of a 0.example/DateTime attribute, where the date is filled in but there is no time information. While incomplete, this value could still be of interest to the client.
  • INVALID: Indicates that the value did not comply with the validation rules.
  • NO_RULES: Indicates that the process could not find any rules to validate the attribute with.
  • NOT_VALIDATED: Validation failed due to any reason, e.g. if there were no rules in the cache and when trying to get the rules, the PID of the attribute definition did not resolve, the attribute definition is not parsable, not accessible or not interpretable.
It is expected that there could be additional specific attribute-defined statuses defined by implementation profiles.
Expected behavior
The FDO attribute processing iterates over the list of attributes using the following steps:
  1. The process checks whether it already has validation rules for the given attribute in its cache. If yes, it proceeds to 2. below. If not, it attempts to acquire them. To do so, it resolves the PID of the attribute definition and extracts the validation rules from the record. If it cannot access, parse or interprete the record, it will set the Attribute_Validation_Status to NOT_VALIDATED. If there are no validation rules in the record, the Attribute_Validation_Status is set to NO_RULES. The Error_Description is set with any error messages that were generated.
  2. The validation rules are checked against the attribute’s value. The process will set the Attribute_Validation_Status to VALID, PARTIALLY_VALID or INVALID and any Error_Description it may have generated.
