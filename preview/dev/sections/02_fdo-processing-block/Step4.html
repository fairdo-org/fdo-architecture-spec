[S-4]: Locating mandatory attributes in FDO record

This step validates the FDO record according to the FDO root profile. Specifically, it verifies that all required FDO root profile attributes are present within the FDO record. This method returns an integer status reflecting the degree of validation.

Inputs:
This step expects the output of : exactly one well-structured FDO record. The input MUST NOT be blank.
Outputs:
A flag status reflecting the success, partial success, and error when trying to find the FDO root profile attributes in the FDO record.
Expected behavior:

This step finds all mandatory attributes as specified by the root profile. It specifically looks for the attributes: 0.FDO/Type, 0.FDO/Profile, and 0.FDO/Data.

The Status value MAY have the following values:

  • COMPLETE (integer value of 0) to indicate that all the FDO root profile fields were successfully found. With such a status, the FDO processing has all the information it needs to proceed to the next step.
  • REQUIRED_FIELDS (integer value of 1) to indicate that only the 0.FDO/Profile and 00.FDO/Type attributes were found.
  • PROFILE_ONLY (integer value of 2) indicates that only the 0.FDO/Profile attribute(s) were found.
  • TYPE_ONLY (integer value of 3) indicates that only the 0.FDO/Type attribute(s) were found.
  • NON_COMPLIANT (integer value of -1) indicates that the FDO root profile attributes were not found. At this point, the FDO record cannot be further processed as an FDO.
10.1234/456
0.FDO/Type 0.example/ResourceTypeGeneral
0.example/ResourceTypeGeneral 0.example/Concept
0.FDO/Profile 10.123/Profile1
0.FDO/Data self
0.FDO/Name Test FDO
0.FDO/Description FDO Test Demonstration
... ...

In this example, returns a COMPLETE status as all the mandatory attributes are present in the FDO record.
