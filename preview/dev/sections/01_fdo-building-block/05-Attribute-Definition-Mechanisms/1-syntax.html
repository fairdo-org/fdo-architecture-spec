Syntax

This attribute validation mechanism SHOULD be used to impose syntactic restrictions on the value space of an attribute definition. Every value of an attribute instantiating an attribute definition that has a syntax MUST comply with these syntactic restrictions.

An attribute value MAY be specified to

  • follow one of the primitive data types “string”, “number”, “integer” or “boolean”,
  • comply with a regular expression,
  • lie within a numeric range,
  • be equal to one element from a whitelist,
  • be not equal to all elements from a blacklist.

To assign a syntax to an attribute definition, the attribute definition record MUST use the profile 0.FDO/AttributeDefSyntax. This profile extends the attribute definition profile with the fields shown in Table 4. The fields encode syntax validation rules. One or several of these fields MAY be used in the attribute definition to define the desired syntax.


This table shows the 0.FDO/AttributeDefSyntax profile. The profile extends the attribute definition profile (see Table 3). All fields that are inherited from the attribute definition profile are left out for brevity. The attributes in the table MUST be instantiated in an attribute definition in order to define a syntax for this attribute definition. This table does not include all information about the attributes. Please resolve the attribute definition PIDs via the Handle System or see the appendix of this document.

0.FDO/PrimitiveDataType There are four possible values: “string”, “number”, “integer”, and “boolean”. All clients MUST support all of these primitive data types. 1
0.FDO/Regex Only applicable if the value of 0.FDO/PrimitiveDataType is “string”. This regular expression in [[ECMA-262]] syntax MUST be successfully validated for all attributes that use this syntax. 0..1
0.FDO/NumericInterval An interval for the value (space of real numbers) that has different meanings depending on the primitive data type. If 0.FDO/PrimitiveDataType is “string”: a range of the length of the value. If 0.FDO/PrimitiveDataType is “number” or “integer”: an interval that restricts the attribute value. 0..1
0.FDO/Whitelist Specifies that a specific value is allowed to instantiate this attribute. If 0.FDO/Whitelist appears multiple times, this gives an exhaustive list of allowed values to instantiate the attribute. No other values than these are permitted. 0..*
0.FDO/Blacklist Specifies that a specific value is not allowed to instantiate this attribute. If 0.FDO/Blacklist appears multiple times, this gives a non-exhaustive list of forbidden values for the attribute. Other restrictions such as 0.FDO/Regex or 0.FDO/NumericInterval still apply. 0..*
