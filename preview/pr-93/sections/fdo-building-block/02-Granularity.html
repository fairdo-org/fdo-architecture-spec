The granularity of FDOs depends on the pragmatic utility decisions made within communities of practice. In order to represent a resource as an FDO, it is necessary to decide which of the resource's parts to use, how they are to be described in the FDO using relevant FDO Profiles, FDO Types and FDO attributes, and how these parts should be related to each other. An example is an MRI scan of the brain. One option is to create one FDO for the entire set of slices. Another option is to create an FDO for each slice, and create a collection FDO referencing all of them. Regardless of the initial granularity decision, it can be revised later to according to the new granularity requirements.

The detailed requirements on granularity are:

[R-GRN-1]
Each FDO MUST represent exactly one logical resource.
[R-GRN-2]
A Resource can be anything such as bit stream, a digital representation of a physical object, a concept or anything a community of interest wants to make accessible as an FDO.
[R-GRN-3]
If an FDO represents a resource consisting of multiple resource it MUST be structured as a collection. It is called a collection FDO.
[R-GRN-4]
An FDO's attributes (see ) MUST describe the FDOs associated resource or collection of resources.
