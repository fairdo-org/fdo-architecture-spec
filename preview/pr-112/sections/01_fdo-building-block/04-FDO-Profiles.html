FDO Profiles

FDO profiles are templates for FDO records. They specify which attributes should be considered in an FDO record. All FDO profiles are themselves fully valid FDOs (see ) that instantiate the profile definition profile (see ).

This section is normative.

[R-PROF-1] FDO Profile

An FDO profile (short: profile) is a machine readable template that MAY be instantiated by FDO records. It defines a set of attribute definitions that MUST be contained in any FDO record instantiating the profile, according to the cardinalities specified in the attribute definitions (see ).

An attribute definition is contained in a profile’s list of attribute definitions if and only if the profile contains an attribute 0.FDO/Attribute (or FDO_Attribute) with a PID resolving to the attribute definition as attribute value.

[R-PROF-2] Additional Attributes

An FDO record MAY contain additional attributes whose attribute definitions are not listed in the profiles it instantiates. profiles MAY prohibit this feature for FDOs that instantiate them by setting the value of the optional 0.FDO/denyAdditionalAttributes attribute to a truthy value. By default, additional attributes are allowed to facilitate the use of multiple FDO profiles in a single FDO record. Explicitly prohibiting additional attributes SHOULD be sparingly used and is NOT recommended.

[R-PROF-3] Profile Compliance

Each FDO record MUST comply with all the profiles it instantiates. A profile is instantiated by using the 0.FDO/Profile attribute, the value of which is the PID of the profile to be instantiated. This means that it MUST successfully validate (see ) against these profiles, at least upon creation and update of the FDO record.

[R-PROF-4] Profiles are FDOs

All profiles MUST at least comply with the FDO root profile and the FDO profile definition profile (see ).

[R-PROF-5] Profile Definition Profile

The FDO profile definition profile defines a set of attribute definitions that MUST be instantiated in the FDO record of each profile. Thus, this profile for all profile FDOs is itself a fully valid FDO that instantiates the root profile and itself. It uses profile extension to inherit the set of attribute definitions of the root profile. In addition to those attributes, the FDO profile definition profile also demands the use of 0.FDO/Name and 0.FDO/Description. The 0.FDO/Attribute attribute is used to specify the set of attribute definitions that MUST be used in any FDO instantiating a profile (profile FDOs included). 0.FDO/ExtendsProfile is used by the profile extension mechanism to indicate the "parent" profile to extend from. The conceptual record of the FDO profile definition profile with the PID 0.FDO/ProfileDef is defined in Table 1.

[R-PROF-6] Profile Registration

Any profile and all attribute definitions it uses MUST be defined in open registries. This is done to promote the findability and reusability of FDO profiles, and thus the interoperability of FDOs. Special rules apply in case profiles are updated, see R11-3.

[R-PROF-7] Root Profile

The root profile defines a minimal set of attribute definitions that MUST be instantiated in any FDO record. All FDOs including the root profile itself MUST comply with the root profile. It is the minimal profile in the sense that it contains the mandatory attribute definitions 0.FDO/Type, 0.FDO/Profile, and 0.FDO/Data that are essential to the interpretability of FDO records. Therefore, compliance with the root profile MUST be checked by all clients even if it is not explicitly included in an FDO record or its profile extension hierarchy. Furthermore, the root profile contains the optional 0.FDO/Metadata attribute to define a generic access point to find associated metadata files. The root profile is defined by the FDO Forum and has the PID 0.FDO/Root. It instantiates itself and 0.FDO/ProfileDef, as it is a profile, and contains the list of attribute definitions shown in Table 2.

[R-PROF-8] Profile Extension Mechanism

profiles SHOULD be extended by other profiles whenever semantically appropriate. The root profile serves as the root of the extension mechanism, meaning, any profile MUST be defined as an extension of the root profile or any of its children.
To extend a profile P1 from a profile P2, the P2 MUST contain an attribute 0.FDO/Extendsprofile or the string FDO_Extends_profile, with the PID identifying P1 as value. In this case, P2 inherits all attribute definitions listed as values to 0.FDO/Attribute in P1. This is recursive, such that the attribute definitions that are listed in profiles that P1 extends from also apply to P2. P2 MAY add further attribute definitions by instantiating 0.FDO/Attribute in its FDO record. The resulting inheritance hierarchy MUST be conflict-free and representable by a directed acyclic graph.
