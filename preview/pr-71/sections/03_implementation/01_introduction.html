Introduction

While all FDOs follow one common concept to make data FAIR, they can still be implemented using various different technologies. In order to guarantee interoperability between existing FDO implementations, it is essential that each implementation clearly specifies how it maps the technology-agnostic concepts of this specification document into a technology-specific implementation (called an FDO implementation profile). Only then, interoperability between different implementations can emerge, i.e., a sequence of steps how to map an FDO in one implementation to an FDO in another implementation can be defined.

[R-Imp-1] Implementation Profile

Each FDO implementation SHOULD specify how it implements the technology-agnostic requirements given in 4. FDO Building Blocks and the processing steps given in 5. Generic FDO Processing. To this end, FDO implementations SHOULD provide details on
  1. how their FDOs implement the building blocks in the chosen technology/implementation, or how they differ from those, and
  2. how their FDOs can be processed by a machine, i.e., describe how processing steps [S-1] - [S-11] work in their implementation, or how the implementation differs from these steps.
This specification uses the building blocks and processing steps to describe the function and characteristic of the various components of the FDO. FDO implementations are not required to implement each of these steps and components as long as they can account for how their implicit assumptions and different components achieve the same processing results.

The complete list of requirements to be specified by an implementation is given below. Some requirements are mandatory (M; MUST be satisfied), some are recommended (R; SHOULD be satisfied), and some are optional (O; MAY be satisfied).

  • For the mandatory points, please describe how your implementation meets these requirements. The aim of the implementation template is to capture all technology-specific adaptations that are made by your implementation, and all conceptional deviations of your implementation from this document. Hence, sometimes it MAY be sufficient to just state that your implementation works exactly similar to the corresponding part in this document.
  • If your implementation does not support one of the recommended points, please shortly explain why this is the case.
  • If your implementation does not support one of the optional points, simply state "[X-Y] This implementation does not support ..." in your implementation specification.

Handle-based FDOs have already started to formulate a Handle-based FDO specification [[?HandleFDOSpec2026]], which you MAY want to look at for reference.
