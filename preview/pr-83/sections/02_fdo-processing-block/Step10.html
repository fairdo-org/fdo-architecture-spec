[S-10]: FDO Data Access

This step attempts to return the FDO’s data bit-sequence or a reference to it. It assumes that was completed and that its status indicates that a 0.FDO/Data field is present (i.e., COMPLETE, DATA_ONLY, TYPE_MISSING, or PROFILE_MISSING). Furthermore, it assumes that was completed successfully.
Inputs
  • a list of validated_attribute as outputted by
Outputs
An object is returned which contains a status variable that details whether extracting the data attributes was successful, and the extracted data attributes themselves. In detail:
  • status:
    • SUCCESS: All 0.FDO/Data attributes are valid, i.e., they all either contain the element self or they point to another attribute in the record that could be extracted.
    • PARTIAL_SUCCESS: Only some of the 0.FDO/Data attributes are valid and could be extracted.
    • FAILURE: No 0.FDO/Data attributes is valid.
  • data_attributes: a list of attributes, each of which contains data either inline, by reference, or its value is self. In the latter case, the record is itself the data of the FDO.
Expected behavior
The 0.FDO/Data attribute by definition either has as its value the string self, or it uses the attribute referencing mechanism to point to other attributes in the record that contains data either by reference or inline. The client finds all 0.FDO/Data attributes that have the validation status VALID. For each of them it performs the following steps:
  • If the 0.FDO/Data attribute has the value self, then (0.FDO/DataAsSelf, self) is added to data_attributes. Proceed to the next 0.FDO/Data.
  • If the 0.FDO/Data attribute has a different value, it is assumed that the attribute referencing mechanism is applied. It is checked whether this value appears in any other attribute as first element. All such other attributes which are found and which have the validation status VALID (0.FDO/Data is said to be pointing to those via attribute referencing) are added to data_attributes. Proceed to the next 0.FDO/Data.
The status is determined as follows:
  • If the data_attributes list is empty, then the status is FAILURE.
  • Else if there are 0.FDO/Data attributes in the record whose value is not self and which are not VALID, or the attribute they are pointing to is not VALID, the status is set to PARTIAL_SUCCESS.
  • Else, all data elements were found and the status is set to SUCCESS.
The client should make the best effort to provide the means to access the data collected in the data_attributes list depending on the manner in which the FDO includes its data. To do so, he may first inspect the attribute definitions of the attributes in the data_attributes list to find further information or instructions.
This example shows an FDO record 1234/000 with three 0.FDO/Data attributes.

1234/000
0.FDO/Type 0.example/ResourceTypeGeneral
0.example/ResourceTypeGeneral 0.example/Collection
0.FDO/Profile 1234/Profile100
0.FDO/Data 0.example/HttpUrl
0.example/HttpUrl https://www.my-server.example/my-file
0.example/HttpUrl https://www.my-server.example/my-file-2
0.example/Description This FDO consists of several data bit-sequences.
0.FDO/Data 0.example/FdoRef
0.example/FdoRef 21.abc/def
0.FDO/Data 0.example/InlineData

Applying the processing step returns
  • status: PARTIAL_SUCCESS, because 0.example/InlineData does not point anywhere in the record (not VALID)
  • data_attributes: [(0.example/HttpUrl, https://www.my-server.example/my-file), (0.example/HttpUrl, https://www.my-server.examplemy-file-2), (0.example/FdoRef, 21.abc/def)]. The client may continue by attempting to follow those references.
