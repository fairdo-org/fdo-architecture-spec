[S-4]: Locating Mandatory Attributes in the FDO Record

This step assumes that successfully returned an FDO record. It validates the FDO record according to the FDO root profile. Specifically, it verifies that all required FDO root profile attributes are present within the FDO record. This method returns an integer status reflecting the degree of validation.

Inputs:
  • an FDO record: This step expects exactly one well-structured FDO record. Typically, this is the output of .
Outputs:
A status that reflects the success, partial success, and error when trying to find the FDO root profile attributes in the FDO record. The status may have the following values:
  • COMPLETE (integer value of 0): All the FDO root profile fields (0.FDO/Type, 0.FDO/Profile, and 0.FDO/Data) were successfully found. With such a status, the FDO processing has all the information it needs to proceed to the next steps.
  • TYPE_MISSING (integer value of 1): 0.FDO/Type is missing.
  • PROFILE_MISSING (integer value of 2): 0.FDO/Profile is missing.
  • DATA_MISSING (integer value of 3): 0.FDO/Data is missing.
  • TYPE_ONLY (integer value of 4): Only 0.FDO/Type was found.
  • PROFILE_ONLY (integer value of 5): Only the 0.FDO/Profile was found.
  • DATA_ONLY (integer value of 6): Only the 0.FDO/Data was found.
  • NON_COMPLIANT (integer value of -1): The FDO root profile attributes were not found. At this point, the FDO record cannot be further processed as an FDO.
Expected behavior:

This step finds all mandatory attributes as specified by the root profile. It specifically looks for the attributes 0.FDO/Type, 0.FDO/Profile, and 0.FDO/Data. Depending on which of the attributes were found, the corresponding status is returned.

10.1234/456
0.FDO/Type 0.example/ResourceTypeGeneral
0.example/ResourceTypeGeneral 0.example/Concept
0.FDO/Profile 10.123/Profile1
0.FDO/Data self
0.FDO/Name Test FDO
0.FDO/Description FDO Test Demonstration
... ...

In this example, returns a COMPLETE status as all the mandatory attributes are present in the FDO record.
