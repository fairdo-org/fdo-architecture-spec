[S-1]: Detection of PIDs

This step determines if the provided string is a PID, whether it is potentially resolvable and how. This may be achieved using any technical solution such as a regular expression based analysis aware of the well known resolvable PID systems. This process may result in false positives, but must avoid false negatives.

Inputs
  • an arbitrary string
Outputs
If the analysis is successful it returns a list of identifier_resolvers objects consisting of:
  • identifier: A syntactically valid PID (there may be multiple outcomes).
  • resolvers: A list with 0 or more resolvers by name in order of probability that may resolve the PID. The resolver should be identified as an FDO.
If the analysis fails, it throws an exception UNRECOGNIZED_IDENTIFIER.
Expected behavior

This step will iterate through a set of well-known PID technologies. Each client may have its own list that it will use when performing this step. A list of PID technologies shall be maintained by the FDO Forum and be updated by the various FDO implementations and by the community at large. These FDOs will include information about the PID syntax and resolvers.

The input string is https://dx.doi.org/10.500/123. would process this as known DOI. There would be two elements in the identifier_resolvers list:

    • identifier: https://dx.doi.org/10.500/123
    • resolvers: [0.example/DNS_RESOLVER]
    • identifier: 10.500/123
    • resolvers: [0.example/DOI_RESOLVER, 0.example/HDL_RESOLVER]

The input string is https://www.ACME.org/fdo/123-245-232. would determine that this is a valid URI and that it could be an FDO because of the “fdo” in path name. But while 123-245-232 looks like an identifier, no known resolver can be found. [S-1] would generate the identifier_resolvers with the following values:

  • identifier: https://www.ACME.org/fdo/123-245-232
  • resolvers: 0.example/DNS_RESOLVER
