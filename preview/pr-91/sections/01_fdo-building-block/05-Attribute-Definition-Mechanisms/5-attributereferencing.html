[R-Attr-14] Attribute Referencing

Attribute referencing is a generic mechanism for redirecting to one or multiple other attributes in the same record. Attribute referencing can, for example, be used to group information for different purposes. Or it can be used very similarly to unions, i.e., to state that an attribute is effectively realized through one or several other attributes in the record, which follow more specific attribute definitions A1,...,An or have labels l1,...,lm, m,n≥0. The mandatory attribute 0.FDO/Data (and actually also the 0.FDO/Type attribute) apply attribute referencing. The reason for this is that data can appear in different forms but need to be deterministically recognizable for a machine:
  • Data may be given by a reference to an external bit-sequence. Then, the 0.FDO/Data attribute would have as its value a URL. (, top-left)
  • Data could also be encapsulated in its own FDO, especially if the FDO is a collection. Then, the 0.FDO/Data attribute would have as its value a reference to an FDO, which possibly follows a specific profile (, top-right).
  • Data could also be inline in the record. Then, the 0.FDO/Data attribute would have as its value a simple data bit-sequence (, bottom-left).
As 0.FDO/Data uses attribute referencing, all these different notions of data references can be unified in one common and harmonized attribute definition 0.FDO/Data. It is essential that the 0.FDO/Data attribute is not redefined over and over by different implementations. Otherwise, a machine would not be able to know which attribute to inspect to find the data bit-sequence of an FDO, irrespective of the implementation. Attribute referencing provides a harmonized entrypoint (0.FDO/Data) for machines to easily detect data (see also ).
If an attribute definition uses the attribute referencing mechanism, we use the following terms for its instantiation:
  • The attribute that instantiates the attribute definition is called the referencing attribute.
  • The attribute that the referencing attribute is pointing to is called the referenced attribute.

To register an attribute definition that uses attribute referencing with the allowed attribute definitions A1,...,An or allowed labels l1,...,lm, the following requirements MUST be fulfilled:

  • The attribute definition record MUST use the profile 0.FDO/AttributeDefAttrRef (that is, it contains the attribute (0.FDO/Profile, 0.FDO/AttributeDefAttrRef)). This indicates that the attribute definition applies the attribute referencing mechanism.
  • The attribute definition record MAY specify a set of attribute definition PIDs A1,...,An and/or labels l1,...,lm, m,n≥0. If these A1,...,An and/or l1,...,lm are specified in the attribute definition record, it means that in an instantiation, the referencing attribute MUST point to a referenced attribute in the same record that instantiates one of A1,...,An or has one of the labels l1,...,lm. In particular,
    • (m=0 ,n=0) The referenced attribute MAY be anything.
    • (m=1, n=0) The referenced attribute MUST have the label l1.
    • (m=0, n=1) The referenced attribute MUST have the attribute definition A1.
    • (m>0, n>0) The referenced attribute MUST have either one of the attribute definitions A1,...,An or one of the labels l1,...,lm.
  • To specify attribute definitions A1,...,An, the attribute definition record MUST contain the attributes (0.FDO/AllowedAttributeInAttrRef, PID of Ai) for i=1,...,n. If n=0, this requirement does not apply. See also Table 8.
  • To specify labels l1,...,lm, the attribute definition record MUST contain the attributes (0.FDO/AllowedPlainNameInAttrRef, li) for i=1,...,m. If m=0, this requirement does not apply. See also Table 8. Specifying labels SHOULD be avoided if it is possible to specify attribute definitions instead.

In the instantiation of an attribute definition that applies attribute referencing, there MAY be cases of consecutive referencing where the referenced attribute itself points to another attribute. All such references within an FDO record MUST form a directed acyclic graph (i.e., no loops allowed). Furthermore, if the referencing attribute apparently does not point to any referenced attribute, the referencing attribute MAY be ignored to handle this error gracefully in certain use cases.
The cardinality of the attribute definition that applies attribute referencing only specifies the occurrence of the referencing attribute and not the occurrence of the referenced attribute.

Attribute referencing is very similar to unions of attribute definitions: In both cases, an attribute definition states that its instantiation validates one of several attribute definitions. However, the slight difference is that for attribute referencing, the referencing attribute also states which of the attribute definitions is actually chosen for the referenced attribute, while this is not stated in the case of unions. If compared to programming principles, attribute referencing behaves somewhat like pointers, whereas unions behave like union types.
